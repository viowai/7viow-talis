# 与 skill/s 配合

先在 Talis 整理需求，再把请求交给当前 AI 工具继续处理。接收端已经安装相应 skill/s 时，可以用它完成写作、设计或研究任务。没有时，这份请求仍是可以直接使用的普通文本。Talis 与这些 skill/s 都可以独立使用。

| 你要完成什么 | Talis 系统模板 | 接收端可选 Skill |
|---|---|---|
| 探索写作方向 | 写作搭档：整理创作需求 | 7viow-writing-partner |
| 修改已有正文 | 文稿编辑：限定改稿范围 | 7viow-writing-editor |
| 理清演示内容 | PPT 文案：整理汇报简报 | 7viow-deck-writing-editor |
| 设计界面或流程 | 界面设计：整理设计简报 | 7viow-ux-ui-design |
| 评审真实体验 | 体验评审：明确检查范围 | 7viow-ux-review |
| 制作演示文件 | PPT 制作：交接确认稿 | 7viow-presentation-production |
| 明确资产研究问题 | 资产研究：明确研究边界 | 7viow-distressed-asset-investment |
| 把研究做成网站 | 研究建站：交接研究成果 | 7viow-research-site-builder |

是否能够安装或调用某个 Skill，取决于该 Skill 的实际发行状态与当前宿主。模板中的名称用于说明可选分工，不代表它已经安装。

## 一个完整例子

你准备介绍一个面向大学生的番茄钟产品，可以先在 Talis 写：

> 我想写一段产品介绍，但还没想好怎么讲。产品只支持 macOS，有25分钟计时和暂停继续，不能增加其他功能。

用追问模式补齐读者、用途和语气，再复制到安装了 Writing Partner 的 AI 工具中探索表达方向。选定方向后，交给 Writing Editor 修改具体文字。只有一次简单改句时，直接在当前 AI 工具完成即可。

如果后续要制作产品页面，带上当前正文、产品事实、已选方向和允许修改范围，交给 UX/UI Design。需要专门检查体验时，再把真实页面或截图交给 UX Review。

## 交接时保留什么

把当前材料和目标读者带给接收工具，说明事实来源、已经确认的决定、本次允许修改的范围以及希望得到的结果。收到反馈后，可以回到 Talis 整理下一次请求，并保存为个人模板。

素材文件通过接收工具自己的附件功能提供。Talis 不会自动读取文本中提到的文件，不会传输附件，也不会替你调用兄弟 Skill。
